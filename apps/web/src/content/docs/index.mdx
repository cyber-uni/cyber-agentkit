## Install

```sh
npm install cyber-agentkit
```

```ts
import { detectHarness, skillsDirectories } from 'cyber-agentkit'

const { harness } = detectHarness() // 'claude-code', 'codex', …, or 'unknown'
if (harness !== 'unknown') skillsDirectories(harness)
```

The package depends on no other agent tool, so any of them can build on it. It also ships as the
`cyber-agentkit` agent plugin and as the `cyber-agentkit` command; see the
[package overview](/cyber-agentkit/packages/agent-kit/).

## What it answers

<CardGrid>
	<Card title="Which harness is running" icon="magnifier">
		`detectHarness()` identifies 13 harnesses from the variables they set, and reports `unknown`
		rather than guess.
	</Card>
	<Card title="Where policy lives" icon="setting">
		`managedPolicyLocations()` lists managed-policy files, MDM domains, registry keys, and
		server-side sources.
	</Card>
	<Card title="Which plugins are present" icon="puzzle">
		`pluginStorage()`, `enabledPlugins()`, and `installedPlugins()` say where plugins live, which
		are enabled, and which folder each one loads from.
	</Card>
	<Card title="How skills are named and found" icon="document">
		`skillInvocation()` returns what a user types to run a plugin skill, and
		`skillsDirectories()` where a harness reads skills from.
	</Card>
	<Card title="Which reference applies" icon="open-book">
		`loadReference()` resolves a named document across the managed, project, user, and plugin
		tiers, merging each override as its frontmatter asks.
	</Card>
</CardGrid>

Every answer rests on a vendor source recorded in
[`.research/harness-detection`](https://github.com/spikyuni/cyber-agentkit/tree/main/.research/harness-detection).
The [package readme](https://github.com/spikyuni/cyber-agentkit/tree/main/packages/agent-kit#readme)
documents each function.
