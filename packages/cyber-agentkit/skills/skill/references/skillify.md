# Skillify: turn work already done into a skill

Turn work already done into a skill. The source shows what was done, not what the skill should do: the author decides.

## 1. Read the source

1. The source is this session's work, unless the description names a document or another skill.
2. If the named source cannot be read, stop and name it. If the session holds no work and no source is named, say
   there is nothing to skillify, point to `create`, and write nothing.
3. If the source holds more than one job and the description names none, propose one skill per job and build none
   until the author picks.
4. Never change the source.

## 2. Decide what varies

Before drafting, propose what the skill generalizes over: what would differ on the next run, such as the repository,
the version, or the target. The author confirms it, at every autonomy level.

## 3. Answer create's questions from the source

Follow [create](create.md) from step 1. Wherever `create` asks the author, answer from the source first, generalized
over what step 2 settled:

- **Place and name:** where the source's work happened, and the job it did.
- **Intent:** the job the source did and the result it handed back.
- **Criteria:** what the author corrected or rejected in the source, and the checks it ran on its result.
- **Shape:** steps the source did the same way every time become scripts. Steps it took only on some paths become
  references.
- **Trigger:** the words the author used to ask for the job.
- **Verification:** the source's requests and inputs, rewritten as made-up cases of the same shape.

Ask the author only what the source leaves open, or where what it did differs from what the skill should do. Show each
answer with the part of the source it came from. The default level is `apply-safe`: write an answer without asking
when `check` passes on it, and ask about the rest. The decisions only the author can make are still asked.
