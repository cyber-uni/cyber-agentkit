`skill doctor [skills...]` examines whether each skill's references work as installed and configured here. It reads the load lines of what the skill actually loads, outside fenced examples: its `SKILL.md` and every file it links or names, and every file those link, wherever each sits. A file read from outside `references/` and `assets/` is passed on as a note pointing to `skill check`, never a failure; a harness's own file under `agents/` is not read until research verifies which harness reads it. It checks each name as `reference check` composes it through the tiers with the skill's own default joined, and, for an interface whose implementations the skill loads, checks the interface and each implementation. Per reference it reports the tiers that answer it, the file on top, and each failure or warning with what to do, such as `reference customize` or `reference migrate`. It changes nothing, and exits 1 only when a reference fails. Given no skill, it examines every skill the detected harnesses load here. `ReferenceLayers.skills.loaded` lists those skills, whether or not they hold a default.
